# dreamd Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single Rust binary, `dreamd`, that consolidates Claude Code auto-memory directories out of band: one `claude -p` worker per session transcript mines insights, one aggregator rewrites a clone of the memory dir, a human reviews the diff and applies it atomically.

**Architecture:** CLI and loopback HTTP API share one `Ctx {Config, Db, Arc<dyn Claude>}`. The pipeline in `dream.rs` is five pure-ish stages (discover → snapshot/clone → reduce transcripts → fan-out workers → aggregate → post-check) with state persisted to SQLite after each stage so the CLI, the API server and a nightly launchd job see the same dreams. All model calls go through the `Claude` trait so tests run against `tests/stub-claude.sh`.

**Tech Stack:** Rust 2021 (1.93), tokio, clap 4 (derive), axum 0.8, rusqlite (bundled), serde/serde_json, ulid, chrono, similar, walkdir, sha2, tempfile, toml, dirs, anyhow/thiserror, tracing/tracing-subscriber, async-trait. Dev: filetime, reqwest (rustls), assert_cmd, predicates.

**Spec:** `docs/superpowers/specs/2026-11-02-dreamd-design.md`

**Compatible with:** devloop skill v0.1+

## Global Constraints

- Never write into an input memory directory except through `apply`, and `apply` only after the live-dir hash equals the snapshot hash (or `--force`).
- `claude` is invoked by PATH name from `config.claude_bin` (default `"claude"`), always with `--output-format json --no-session-persistence` and stdin from `/dev/null`; output is a JSON array whose last element is `type: "result"`.
- Exit codes: `0` ok, `2` gate-skipped / nothing to do, `3` refused (hash mismatch, bad status), `4` dream failed.
- Env overrides for tests: `DREAMD_CONFIG` (config file path), `DREAMD_DATA_DIR`, `DREAMD_CONFIG_DIRS` (colon-separated), `DREAMD_CLAUDE_BIN`.
- Defaults from the spec: `min_hours = 24`, `min_sessions = 3`, `port = 7720`, worker `model = "sonnet"`, `effort = "low"`, `concurrency = 3`, `timeout_secs = 600`, `max_transcript_bytes = 200000`; aggregator `model = "opus"`, `effort = "high"`, `timeout_secs = 1800`; schedule `hour = 3`, `minute = 30`, `auto_apply = false`; live-session exclusion window 10 minutes; session cap 100 newest-first.
- API binds `127.0.0.1` only; errors are RFC 7807 `application/problem+json`.
- `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test` green before every commit.

## Review Focus

1. A transcript JSONL with a malformed line or a multi-megabyte base64 image block must reduce without panicking and without the image bytes reaching the digest (Task 4).
2. A memory dir that *already* violates conventions (missing frontmatter, dangling `MEMORY.md` link) must not fail the dream for pre-existing violations; only violations introduced in `out/` fail it (Task 7).
3. A worker whose `claude -p` exits non-zero, prints non-JSON, or reports `is_error: true` is recorded as failed for that session; the dream fails only if every worker fails (Task 6).
4. A session file modified in the last 10 minutes is a live session and is excluded from candidates even if it is newer than `last_dreamed_at` (Task 3).
5. `apply` when the live memory dir changed since the snapshot exits 3 and leaves the live dir untouched; a crash between backup and swap leaves either the old dir or the new dir, never a half copy (Task 9).
